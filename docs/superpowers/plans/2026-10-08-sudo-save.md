# Sudo-save on permission-denied — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user retry a permission-denied file save with elevated privileges — for local files via the OS's native `pkexec`/`osascript` prompt, and for remote files opened through a (newly wired-up) standalone SFTP-XP connection via `sudo` over the existing SSH channel.

**Architecture:** Three independent-but-sequential slices. (A) Wire Tabby's native `ProfileProvider` mechanism to a dormant code path (`SftpConnectionManager`/`SftpConnection`, `ssh2`-backed) so standalone remote connections become reachable from the UI at all. (B) On a local save failing with `EACCES`/`EPERM`, offer a "Retry with sudo" button that re-writes the file through `pkexec` (Linux) or `osascript ... with administrator privileges` (macOS); unsupported on Windows. (C) On a remote save over a standalone (`ssh2`) connection failing with SFTP status 3 (`PERMISSION_DENIED`), offer the same button, which runs `sudo -S dd` over an SSH exec channel, trying the connection's own password first and falling back to a password-prompt dialog. Connections opened from an existing SSH terminal tab (`TabbySftpFileSystem`) are untouched — no sudo retry is offered there.

**Tech Stack:** Angular 15, TypeScript, `ssh2` (for the standalone connection + exec channel), Node `child_process`/`fs/promises`, Tabby's `tabby-core` plugin APIs (`ProfileProvider`, `NgbModal`, `PlatformService`, `NotificationsService`).

**Spec:** `docs/superpowers/specs/2026-10-08-sudo-save-design.md`

## Global Constraints

- No sudo/login password is ever written to disk or to application config; it only lives in memory for the duration of a single retry call (spec: Non-goals).
- The "Retry with sudo" button must never appear on Windows for local files (spec: Scope / Part B).
- The "Retry with sudo" button must never appear for `TabbySftpFileSystem` (tab-derived) remote connections — only for standalone `SftpConnection` (`ssh2`) ones (spec: Scope / Part C).
- Paths/content passed to local `spawn()` calls go as discrete argv elements, never through a shell string (spec: Part B).
- The remote path embedded in the `sudo ... dd of=...` command string is POSIX shell-quoted, since SSH `exec` always runs through the remote shell (spec: Part C).
- The remote sudo exec channel's stdin carries *only* the sudo password, never the file content being written — the file data is staged via an unprivileged temp file and read by path (`dd if=<temp>`), specifically so a `sudo` that doesn't prompt (NOPASSWD, cached credential) can never leak the password into the target file or corrupt it (found during Task 6's implementation; corrected in the plan before being finalized).
- This repository has no test runner configured (`package.json` has no `test` script, no Jest/Vitest, no `*.spec.ts` files) and the Electron app cannot be launched in this environment (missing native `rspack` binding). Every task's "test" step is therefore one of: a standalone Node verification script for pure logic (run with plain `node`, no TS compiler needed — logic is duplicated inline in the script), `tsc --noEmit` for compile correctness, or an explicit manual verification checklist item for anything requiring the real Electron app / a real sudo prompt / a real SSH server. Do not invent a test framework that isn't there.

## Review Focus

- A local or remote path containing a single quote (e.g. a file named `it's a config.conf`) must still save correctly with sudo, not break the quoting and silently corrupt the command — pinned by Task 4's and Task 6's verification scripts.
- Cancelling the native `pkexec`/`osascript` prompt (no password entered) must leave the file dirty with a clear error notice, never a false "Saved" — manual check added to Task 5.
- Opening SFTP-XP from an existing SSH tab (`TabbySftpFileSystem`) and hitting a permission-denied save must show exactly today's three-button dialog with no "Retry with sudo" option — manual check added to Task 8.
- Entering the wrong sudo password in the remote password dialog must re-prompt (not fail outright, not loop silently forever without feedback) — manual check added to Task 8.
- A profile created through the new "SFTP-XP Connection" entry point with no password (key-only auth) must go straight to the password dialog on a permission-denied save, never attempt a silent retry with an empty password — pinned by Task 8's implementation (`connection.password` falsy check) and its manual check.
- A remote host where `sudo` does not actually prompt (NOPASSWD sudoers entry, or an already-cached credential) must not leak the password into the saved file or corrupt its content — this is why `writePrivileged` stages data in a temp file and reads it by path rather than streaming it down the same stdin as the password; a reviewer should specifically check the exec channel's stdin never carries file data (Task 6).
- The remote staging temp file must never exist, even momentarily, with more than owner-only permissions, and its path must not be guessable — a reviewer should confirm `writeFileExclusive` sets `mode: 0o600` in the same `createWriteStream` call that creates the file (not a separate later `chmod`) and uses `flags: 'wx'` (exclusive create) with a `crypto.randomBytes`-derived name, not `Math.random()`/`Date.now()` (Task 6).

- [ ] **Step 1: Create the service**

Create `src/core/privileged-write.service.ts`:

```ts
import { Injectable } from '@angular/core';
import { spawn } from 'child_process';
import { randomBytes } from 'crypto';
import * as fsp from 'fs/promises';
import * as os from 'os';
import * as path from 'path';
import { shellQuotePosix } from './shell-quote';

const escapeForAppleScriptString = (value: string): string =>
  value.replace(/\\/g, '\\\\').replace(/"/g, '\\"');

/** Builds the `osascript -e ...` argv for privileged-copying `tempPath` onto `targetPath` on macOS. Exported standalone so its quoting can be checked without spawning a process. */
export function buildMacSudoCommandArgs(targetPath: string, tempPath: string): string[] {
  const shellCommand = `dd if=${shellQuotePosix(tempPath)} of=${shellQuotePosix(targetPath)} status=none`;
  const script = `do shell script "${escapeForAppleScriptString(shellCommand)}" with administrator privileges`;
  return ['-e', script];
}

function runProcess(command: string, args: string[], stdin?: Buffer): Promise<void> {
  return new Promise((resolve, reject) => {
    const child = spawn(command, args, { stdio: ['pipe', 'ignore', 'pipe'] });
    let stderr = '';
    child.stderr.on('data', (chunk: Buffer) => {
      stderr += chunk.toString();
    });
    child.on('error', reject);
    child.on('close', (code) => {
      if (code === 0) {
        resolve();
      } else {
        reject(new Error(stderr.trim() || `${command} exited with code ${code}`));
      }
    });
    if (stdin) {
      child.stdin.write(stdin);
    }
    child.stdin.end();
  });
}

/**
 * Writes a local file with elevated privileges via the OS's native
 * authentication prompt (`pkexec` on Linux, `osascript` on macOS). Not
 * supported on Windows — check `isSupported` before offering this.
 *
 * The macOS temp file is created exclusively (`flag: 'wx'`) with owner-only
 * permissions (`mode: 0o600`) set in the same call, and named with
 * `crypto.randomBytes` rather than `Math.random()`/`Date.now()` — the same
 * hardening applied to the equivalent remote temp file in `SftpConnection`
 * (`src/sftp/sftp.service.ts`), added here for consistency even though the
 * local threat model (a per-user `$TMPDIR`, not a shared remote host) is
 * weaker.
 */
@Injectable({ providedIn: 'root' })
export class PrivilegedWriteService {
  static readonly isSupported = process.platform === 'linux' || process.platform === 'darwin';

  async writeLocalFile(targetPath: string, content: Buffer): Promise<void> {
    if (process.platform === 'linux') {
      await runProcess('pkexec', ['dd', `of=${targetPath}`, 'status=none'], content);
      return;
    }
    if (process.platform === 'darwin') {
      const tempPath = path.join(os.tmpdir(), `sftp-xp-sudo-${randomBytes(16).toString('hex')}`);
      await fsp.writeFile(tempPath, content, { mode: 0o600, flag: 'wx' });
      try {
        await runProcess('osascript', buildMacSudoCommandArgs(targetPath, tempPath));
      } finally {
        await fsp.rm(tempPath, { force: true });
      }
      return;
    }
    throw new Error('Elevated save is not supported on this platform.');
  }
}
```

**Security-critical design note (1):** the exec channel's stdin must carry
*only* the sudo password, never the file content. If the password and the
file data were both written to the same stdin stream (as an earlier draft
of this plan did), a `sudo` that does *not* actually prompt — a NOPASSWD
sudoers entry, or an already-cached credential — would pass the whole
stdin stream straight through to `dd` unconsumed, writing the plaintext
password into the target file as its first line: a real credential leak
plus silent data corruption, not just a theoretical risk, since NOPASSWD
configs are common on automated/server hosts. The fix: stage `data` in an
unprivileged remote temp file first, then have the privileged `dd` read
*from that file* (`if=`) rather than from stdin — so stdin is free to
carry only the password, and an unconsumed password line on stdin is
simply discarded by `dd` (which isn't reading stdin at all), never written
anywhere.

**Security-critical design note (2):** that temp file must be created with
owner-only permissions *atomically at creation time* — not written first
with default (often world-readable) permissions and `chmod`'d afterward,
which leaves a real window where another local user on the same remote
host could read the staged content, or race to pre-create something at the
guessable path before this code does. Create it via `createWriteStream`
with `flags: 'wx'` (`O_CREAT|O_EXCL` — fails if the path already exists,
so there's no silent overwrite of something an attacker planted first) and
`mode: 0o600` passed together, and name it with `crypto.randomBytes`
(cryptographically unpredictable), not `Math.random()`/`Date.now()`
(guessable).

Add this import near the top of the file, with the other imports:

```ts
import { randomBytes } from 'crypto'
```

**Security/correctness design note (3), found by the final whole-branch
review:** an `ssh2` exec channel's main (stdout) side is a paused Readable.
If nothing ever reads it — no `'data'` listener, no `.resume()` — it never
reaches `'end'`, and `ssh2` only emits the channel's `'close'` event once
the readable side has ended. Since `'close'` is the only place this method
resolves or rejects, skipping `stream.resume()` means **the promise never
settles and a remote sudo save hangs forever**, on every call. Also,
`exitCode` must start as `null`, not `0`: if the SSH connection drops and
the channel reaches `'close'` without ever emitting `'exit'` (e.g. a
dropped connection), an `exitCode` that defaulted to `0` would resolve as
a false "Saved" even though nothing was written.

```ts
  /**
   * Re-attempts a write with `sudo`, over the same SSH connection. Stages
   * `data` in an unprivileged remote temp file (created exclusively, with
   * owner-only permissions set atomically — see the design notes above),
   * then copies it into place with a privileged `dd` that reads the temp
   * file by path — so the exec channel's stdin carries only the sudo
   * password, never file content.
   */
  async writePrivileged(remotePath: string, data: Buffer, password: string): Promise<void> {
    const tempPath = `/tmp/.sftp-xp-sudo-${randomBytes(16).toString('hex')}`
    let tempFileCreated = false
    try {
      await this.writeFileExclusive(tempPath, data)
      tempFileCreated = true
      await new Promise<void>((resolve, reject) => {
        const command = `sudo -S -p '' dd if=${shellQuotePosix(tempPath)} of=${shellQuotePosix(remotePath)} status=none`
        this.client.exec(command, (err, stream) => {
          if (err) {
            reject(err)
            return
          }
          let stderr = ''
          let exitCode: number | null = null
          // Drain stdout so the channel can reach 'close' — a paused
          // Readable that's never read never emits 'end', which ssh2's
          // channel-close handling waits on.
          stream.resume()
          stream.stderr.on('data', (chunk: Buffer) => {
            stderr += chunk.toString()
          })
          stream.on('exit', (code: number) => {
            exitCode = code
          })
          stream.on('close', () => {
            if (exitCode === 0) {
              resolve()
              return
            }
            if (/incorrect password|try again|no password was provided/i.test(stderr)) {
              reject(new SudoAuthError(stderr.trim() || 'Incorrect sudo password'))
            } else {
              reject(new Error(stderr.trim() || `sudo exited with code ${exitCode ?? 'unknown'}`))
            }
          })
          stream.stdin.write(`${password}\n`)
          stream.stdin.end()
        })
      })
    } finally {
      // Only clean up a file this call actually created — if
      // writeFileExclusive itself failed (e.g. a path collision), there is
      // nothing of ours to remove, and the path might belong to something
      // else entirely.
      if (tempFileCreated) {
        await this.remove(tempPath, false).catch(() => undefined)
      }
    }
  }

  /**
   * Creates `path` exclusively (fails rather than silently overwriting if it
   * already exists) with owner-only permissions set atomically at creation
   * — there is never a window where the file exists with more permissive
   * (e.g. default-umask) access.
   */
  private async writeFileExclusive(path: string, data: Buffer): Promise<void> {
    await new Promise<void>((resolve, reject) => {
      const stream = this.sftp.createWriteStream(path, { flags: 'wx', mode: 0o600 })
      stream.on('error', reject)
      stream.on('close', () => resolve())
      stream.end(data)
    })
  }

        this.client.exec(command, (err, stream) => {
          if (err) {
            settle(() => reject(err))
            return
          }
          let stderr = ''
          let exitCode: number | null = null
          // Drain stdout so the channel can reach 'close' — a paused
          // Readable that's never read never emits 'end', which ssh2's
          // channel-close handling waits on.
          stream.resume()
          stream.stderr.on('data', (chunk: Buffer) => {
            stderr += chunk.toString()
          })
          stream.on('exit', (code: number) => {
            exitCode = code
          })
          stream.on('close', () => {
            if (exitCode === 0) {
              settle(resolve)
              return
            }
            if (/incorrect password|try again|no password was provided/i.test(stderr)) {
              settle(() => reject(new SudoAuthError(stderr.trim() || 'Incorrect sudo password')))
            } else {
              settle(() => reject(new Error(stderr.trim() || `sudo exited with code ${exitCode ?? 'unknown'}`)))
            }
          })
          stream.stdin.write(`${password}\n`)
          stream.stdin.end()
        })
      })
```

30 seconds is generous for sending one short password line and copying a
typical edited text file locally on the remote host via `dd` — it should
never be reached in normal operation; it exists purely as a last-resort
safety net.
